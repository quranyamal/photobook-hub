# ADR-0007 Storage Strategy

Status: Accepted

Date: 2026-08-23

---

## Context

PhotoBook Hub allows customers to upload photos that are later used to compose
printable photobooks. These uploaded files must be stored durably, served back
to the browser for preview, and eventually handed off to the production team for
printing.

At MVP stage the platform runs on a single server with no external object
storage. The priorities are:

1. Get uploads working with zero infrastructure overhead
2. Keep the application code decoupled from the storage medium
3. Establish a clear migration path toward production-grade storage

Three storage tiers are relevant to this project's roadmap:

| Tier | Medium | When |
|---|---|---|
| MVP | Local filesystem | Now |
| Phase 2 | MinIO (self-hosted S3-compatible) | When persistent volume storage is needed |
| Phase 3+ | AWS S3 / GCS | When cloud infrastructure is adopted |

---

## Decision

Introduce a `StorageProvider` interface in `src/server/storage.ts` that abstracts
upload, URL resolution, and deletion behind three operations:

```ts
interface StorageProvider {
  upload(key: string, data: Buffer, mimeType: string): Promise<void>;
  getUrl(key: string): string;
  delete(key: string): Promise<void>;
}
```

A **storage key** is a path-like string that uniquely identifies a file
(e.g. `projects/cm5abc/photos/cm5xyz.jpg`). Keys are generated by route
handlers; the storage layer has no opinion on naming.

### MVP — Local Filesystem (`LocalStorage`)

- Files are written to `UPLOAD_DIR` (defaults to `.uploads/` in the project
  root, configurable via environment variable)
- Subdirectories are created automatically on upload
- `getUrl(key)` returns `/api/files/${key}`, served by a dedicated route
  handler (added in Sprint 3 Session 2)
- `delete` silently ignores missing files (`ENOENT`)

A singleton `storage` instance is exported from `src/server/storage.ts`. All
route handlers import `storage`, not `LocalStorage` directly — this is the
only point that changes when switching implementations.

### Migration Path

Switching from local filesystem to MinIO or S3 requires:

1. Install the relevant SDK (`@aws-sdk/client-s3` or `minio`)
2. Implement `StorageProvider` in a new class (e.g. `S3Storage`)
3. Replace the singleton assignment in `storage.ts`
4. Update `UPLOAD_DIR` / bucket env vars

No route handler, service, or UI code needs to change.

---

## Consequences

### Positive

* Zero infrastructure overhead at MVP — no object storage service to run
* Route handlers are storage-agnostic from day one
* Swapping implementations is a one-file change
* `UPLOAD_DIR` is configurable, making testing straightforward (each test
  gets an isolated `os.tmpdir()` directory)

### Negative

* Local filesystem storage is not suitable for multi-instance deployments —
  files written to one instance are invisible to others
* `/tmp` or local directories are not durable across container restarts unless
  a persistent volume is mounted
* Serving uploaded files through a Next.js route handler (`/api/files/...`)
  adds latency compared to a CDN-backed object store

---

## Alternatives Considered

### Upload directly to S3 from day one

Use pre-signed URLs to upload files from the browser directly to S3, bypassing
the server.

Rejected because: requires AWS credentials, bucket policy configuration, and
CORS setup before the first feature is working. The operational overhead is not
justified at MVP stage.

### MinIO from day one

Run MinIO alongside PostgreSQL and Jaeger in Docker Compose, providing an
S3-compatible API from the start.

Rejected because: adds another service to the local dev stack and a container
to maintain. The `StorageProvider` interface means MinIO can be introduced in
Phase 2 without touching application code — there is no benefit to running it
earlier.

### Store files as BLOBs in PostgreSQL

Upload binary data into a `bytea` column directly in the database.

Rejected because: large binary data in PostgreSQL degrades query performance
and backup size. Not a viable long-term strategy for image files up to 20 MB.
